# راهنمای جامع معاملات کاغذی زنده (Paper Trading Guide)

> **امنیت و معماری**: این ماژول کاملاً **فقط‌خواندنی (Read-Only)** است. هیچ کلید API خصوصی، امضای تراکنش یا قابلیت ارسال سفارش به صرافی در کل کدبیس وجود ندارد. دریافت داده‌ها منحصراً از Endpointهای عمومی رایگان صرافی بایننس صورت می‌گیرد.

---

## ۱. ساختار دفاتر معاملاتی (Trading Books)

سیستم به صورت همزمان دو دفتر موازی را روی داده‌های زنده اجرا می‌کند:

| مشخصه | دفتر A (Book A: F3 Active) | دفتر B (Book B: C1L Conservative) |
| :--- | :--- | :--- |
| **استراتژی پایه** | `fisherMode: 'confirm'` | `fisherMode: 'extra-trigger'` |
| **جهت معامله** | فقط‌خرید (`tradeMode: 'long-only'`) | فقط‌خرید (`tradeMode: 'long-only'`) |
| **سایز هر پوزیشن** | ۳٪ کل سرمایه حساب | ۲٪ کل سرمایه حساب (محافظه‌کارانه) |
| **سقف پوزیشن همزمان** | حداکثر ۱۰ پوزیشن **به‌ازای هر حساب (هر بازار/تایم‌فریم)** | حداکثر ۵ پوزیشن **به‌ازای هر حساب (هر بازار/تایم‌فریم)** |
| **سقف مواجهه کل** | حداکثر ۳۰٪ سرمایه **به‌ازای هر حساب (هر بازار/تایم‌فریم)** | حداکثر ۲۰٪ سرمایه **به‌ازای هر حساب (هر بازار/تایم‌فریم)** |
| **مکانیزم اجرای ورود** | قیمت بازگشایی کندل بعد (`entryFill: 'nextOpen'`) | قیمت بازگشایی کندل بعد (`entryFill: 'nextOpen'`) |
| **تریلینگ‌استاپ** | پله‌ای ۵٪ / ۳٪ / ۱.۵٪ | پله‌ای ۵٪ / ۳٪ / ۱.۵٪ |
| **فیلترهای تکنیکال** | Kijun Slope + Structure + Stoch 14/3/3 (30/70) | Kijun Slope + Structure + Stoch 14/3/3 (30/70) |
| **کارمزد و اسلیپیج** | کارمزد ۰.۱٪ + اسلیپیج فرضی ۰.۰۵٪ در ورود و استاپ‌ها | کارمزد ۰.۱٪ + اسلیپیج فرضی ۰.۰۵٪ در ورود و استاپ‌ها |

### بازارهای تحت پوشش (۴ حساب مستقل به‌ازای هر دفتر)
- `BTCUSDT` در تایم‌فریم‌های `1h` و `4h`
- `ETHUSDT` در تایم‌فریم‌های `1h` و `4h`

> **نکته مهم در رابطه با سقف‌ها و ریسک**:  
> سقف‌های `maxOpenPositions` و `maxTotalExposurePercent` به‌صورت کاملاً ایزوله و مستقل **به‌ازای هر حساب مستقل** (هر جفت‌ارز و تایم‌فریم) تعریف و پایش می‌شوند. شاخص افت سرمایه (Drawdown) تجمیعی در گزارش، نسبت به **مجموع کل سرمایه ۴ حساب** محاسبه می‌گردد و بیانگر ریسک پورتفولیو است، نه یک حساب واحد.

## ۲. دستورهای اجرا (Execution Commands)

### الف) اجرای تک‌مرحله‌ای (One-Shot Execution)
برای به‌روزرسانی کندل‌ها، پردازش سیگنال‌ها، به‌روزرسانی پوزیشن‌ها و تولید گزارش در یک نوبت:
```bash
npm run paper:once
```

### ب) اجرای پیوسته به صورت دیمون (Watch Mode)
برای اجرای خودکار در پس‌زمینه و بررسی کندل‌های جدید در فواصل زمانی منظم (پیش‌فرض هر ۵ دقیقه):
```bash
npm run paper:run
```
برای تغییر بازه زمانی بررسی (مثلاً هر ۶۰ ثانیه):
```bash
npx tsx src/paper/cli.ts --watch --interval 60
```

## ۳. اتوماسیون دوره‌ای با GitHub Actions (Hourly Execution)

یک فرآیند خودکار ابری در مسیر `.github/workflows/paper.yml` تعبیه شده است:
- **زمان‌بندی**: سر ساعت در دقیقه ۵ هر ساعت (`5 * * * *`).
- **قابلیت اجرای دستی**: از تب Actions در گیت‌هاب با کلیک روی Run workflow (`workflow_dispatch`).
- **همزمانی محافظت‌شده**: استفاده از `concurrency: paper` جهت ممانعت از تداخل چندین اجرای همزمان و خطای push.
- **تغییرات کامیت‌شده**: فایل‌های `data/paper/*.jsonl`، `data/paper/state_*.json`، `data/paper/forward_start.json` و `docs/paper/PAPER_LATEST.md` با پیام `"chore(paper): hourly update"`.
- **فعال‌سازی در مخزن**: نیازی به تنظیم هیچ Secret ندارد؛ صرفاً اطمینان حاصل فرمایید که گزینه **Read and write permissions** برای `GITHUB_TOKEN` در تنظیمات مخزن (*Settings > Actions > General > Workflow permissions*) فعال باشد.

## ۴. ساختار فایل‌ها و مسیرهای ذخیره‌سازی

- **ساعت و مبدأ روبه‌جلو (Forward Clock)**:
  - `data/paper/forward_start.json`  
  تایم‌استمپ تثبیت‌شده و دائمی آغاز آزمون روبه‌جلو.
- **داده‌های کندل خام**:
  - `data/paper/{symbol}_{tf}.jsonl`  
  کندل‌های بسته‌شده قطعی با ساختار خط‌به‌خط JSON (پنجره فقط‌رشد حداقل ۱,۲۰۰ کندل).
- **وضعیت لحظه‌ای هر بازار**:
  - `data/paper/state_{book}_{symbol}_{tf}.json`  
  موجودی نقد، ارزش کل، پوزیشن‌های باز، سابقه معاملات و متریک‌ها.
- **گزارش مقایسه‌ای و تحلیلی**:
  - `docs/paper/PAPER_LATEST.md`  
  گزارش جامع شامل مقایسه دو دفتر، تفکیک بازارها، فانل سیگنال‌ها و بازپخش روزانه.
- **سندهای پیش‌ثبت رسمی**:
  - `docs/review/PREREGISTERED_PU.md` و `docs/review/PREREGISTERED_PT.md`

## ۵. مکانیزم توقف اضطراری (HALT Circuit Breaker)

سیستم مجهز به سوئیچ ایمنی خودکار برای مهار ریسک نزولی است:

1. **تریگر خودکار**:  
   چنانچه بیشینه افت سرمایه (Drawdown) هر دفتری در حین اجرا به **$\ge 10.0\%$** برسد، سیستم فوراً فایل پرچم توقف را با اطلاعات ماندگار JSON ایجاد می‌کند:
   - `data/paper/HALT_A` برای دفتر A
   - `data/paper/HALT_B` برای دفتر B
2. **رفتار هنگام توقف (HALT)**:
   - ثبت هرگونه **ورود جدید ممنوع** شده و سیگنال‌های جدید رد می‌شوند.
   - پوزیشن‌های بازی که از قبل وجود داشته‌اند همچنان طبق منطق تریلینگ‌استاپ پایش شده و با رسیدن به حد ضرر به طور ایمن بسته می‌شوند.
3. **ری‌ست دستی (Manual Reset)**:
   برای رفع وضعیت توقف پس از بررسی علت، کافی است فایل پرچم حذف شود:
   ```powershell
   Remove-Item data/paper/HALT_A -Force
   # یا در لینوکس:
   # rm data/paper/HALT_A
   ```

## ۶. پروتکل ری‌ست کل سیستم (Full System Reset)

> [!WARNING]
> حذف مبدأ روبه‌جلو تاریخچه آزمون فوروارد را باطل می‌کند و شمارنده معاملات از صفر شروع می‌شود.

در صورت نیاز به شروع مجدد کل محیط آزمون روبه‌جلو:
```powershell
# حذف مبدأ ساعت و وضعیت حساب‌ها
Remove-Item data/paper/forward_start.json -Force
Remove-Item data/paper/state_*.json -Force
Remove-Item data/paper/HALT_* -Force -ErrorAction SilentlyContinue
```
در اجرای بعدی `npm run paper:once`، مبدأ ساعت جدید به صورت خودکار با زمان آخرین کندل ثبت خواهد شد.

## ۷. پروتکل ارزیابی و تصمیم‌گیری

مطابق با تعهدات ثبت‌شده در `PREREGISTERED_PT.md` و `PREREGISTERED_PU.md`:
- ارزیابی عملکرد و مقایسه دو دفتر صرفاً پس از سپری شدن **حداقل ۹۰ روز تقویمی** و بسته شدن **حداقل ۳۰ معامله روبه‌جلو** در هر دفتر انجام می‌پذیرد.
- پیش از احراز این دو شرط، شاخص‌های آماری در گزارش با برچسب صریح `N/A (نمونه ناکافی: n=...)` نمایش داده می‌شوند و هیچ تصمیمی اتخاذ نمی‌شود.
- معیار پذیرش صحت اجرا: انطباق با بازپخش بک‌تست باید انحراف بازدهی $\le 20\%$ نسبی و اختلاف معاملات $\le 15\%$ باشد.
